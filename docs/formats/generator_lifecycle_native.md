# Generator creator identity and bounds publication

The successful birth path at `004374aa` writes the producer pointer to child
`+0x2b4`; `004374b9` captures producer `+0xb8` in child `+0x2b0`. The port
therefore assigns both `generatorParent` and the existing general creator/UID
link before later manager visits. Native contact and ancestry consumers see
this identity; stable-population accounting retains its separate generator link.
Existing save fields retain the new link without a schema change. Older saved
children with no general creator remain as saved; ancestry is not reconstructed.

During an inactive occupancy attempt, `004373cb` and `00437418` publish temporary
bounds enable/disable through `0040ef20`, including blocked attempts. Appearance
at `0043745a` and disappearance at `0043751f` also publish immediately. The port
updates its navigation graph at those boundaries, including the first activation
of an initially inactive producer. These are bounds changes; sprite visibility,
products, timers and population limits retain their existing behavior.

`generator_native_world_test` exercises actual births, creator UID validation,
ancestry traversal, population caps, first activation, blocked queries and disk
continuation. The inactive-start cases are synthetic: all 84 shipped production
records start active. Retained original-instruction controls establish these
specific call/field boundaries, rather than a complete Windows gameplay replay.
